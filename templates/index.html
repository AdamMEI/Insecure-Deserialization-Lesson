Insecure Deserialization Lesson

Overview

Vulnerability

Serialization is the process of converting data (often an object) to a format that is easier to store or transfer. It often means turning something into a string of bytes or text, then saving that to a file or sending it over a network. When the data is needed again, it is deserialized back into its original state.

This can be dangerous, however. If the user has control over what information is deserialized, then they can alter the information to instead contain their own serialized object. When that object is deserialized, it can perform arbitrary code (such as os.system("rm -rf").

Exploit

When looking for potential exploits, it's important to check cookies and local storage to see if they contain any useful information.

To check cookies, press Ctrl + Shift + I on Windows/Linux or Cmd + Option + I on Mac. Navigate to Storage on Firefox or Application on other browsers. Finally, click on the web address under Cookies.

Try leaving a comment. A new entry should pop up with the name comments. The value consists of seemingly random lower and uppercase letters, implying that it may be base 64 encoded. This implies that the comments may be stored as base 64 encoded data in the cookies, then loaded when you reload the page. To confirm this, try reloading the page, and see if your comment stays. If it does, then try deleting that cookie entry and reloading it again. The new comment should go away.

Patch

The vulnerability stems from the inherit danger in deserializing user-controlled information. To patch it, we have two options:

  • Don't store the serialized comments in a place where users can alter them
  • Don't serialize and deserialize them as potentially dangerous objects
For this lesson, we will choose the second option. Instead of serializing the comments as objects using pickles, we will serialize them as a JSON list.
